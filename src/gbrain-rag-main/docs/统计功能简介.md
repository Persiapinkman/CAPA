# 统计功能简介

## 功能简介

本项目在检索增强生成 (RAG) 的基础上，新增了**智能聚合统计（Agentic Aggregate）功能**。当用户提出需要进行全局数据统计、数量计算或状态汇总类的查询（例如：“现在总共部署了多少个模型？”）时，系统能够通过智能路由识别用户意图，并将此类请求直接交由分析代理（Agent）进行处理，而不是使用常规的文本块检索和阅读理解。

## 工作原理

1. **统计意图识别**：接口收到 `query` 后，会先通过本地 query intent 逻辑识别“多少个 / 数量 / 总数 / 总共 / 统计”等全量聚合意图，并排除“OID 是什么”“负责人是谁”“平台是什么”这类字段值查询，避免把普通查字段问题误判成统计问题。
2. **本地结构化捷径**：对于常见统计问题，系统优先读取 SQLite 中的结构化 metadata 行，例如 `table` 的模型发版汇总记录或 `adela` 的部署记录。代码会根据 query intent、查询扩展词、平台条件和字段加权评分匹配候选行，再按统计口径执行去重或计数；例如 Adela 模型数按 `model_name` 去重，部署记录数按记录数统计。
3. **LLM 统计计划**：当本地捷径不足以覆盖问题时，系统会让 LLM 只输出结构化 JSON 计划，包括数据源、统计操作、去重字段、字段过滤条件和统计口径。LLM 不直接给出最终数字；后续仍由代码读取全量结构化行，按 `field_conditions` 过滤，并执行 `count_unique` 或 `count_records`。
4. **短路响应 (Short-circuit Response)** 当结构化统计成功完成并产出最终结果后，系统会：

   - 产生类似于 `answered_by_agentic_aggregate` 的状态消息。
   - 跳过其他不相关的数据源检索（标记为 `skipped_by_agentic_aggregate`），直接返回确切答案，从而**大幅降低无效的检索消耗和推理延迟**。

## 实现特点

统计功能不是简单基于关键词在文本中命中后累加，也不是针对少数问题写死答案。关键词只用于识别“是否可能是统计请求”的入口判断；真正的统计基于结构化字段和明确口径执行。系统会把用户问题映射到 `table` 或 `adela` 等结构化数据源，结合字段画像、规范字段名、查询扩展词和字段条件生成可执行计划，再由代码完成过滤、去重和计数。

因此，这个功能的关键数字来自确定性的结构化执行结果，而不是 LLM 根据检索片段猜测；过滤条件也必须绑定到具体字段，例如 `model_name`、`platform`、`label_list`、`supported_device`、`did`、`rid` 等。这样可以降低对表面关键词的过拟合：即使用户换一种问法，只要语义对应到同一统计口径，系统仍能复用相同的结构化字段和计数逻辑。

## 接口响应示例

在客户端中，调用统一查询接口时，若触发了此统计功能，其 `source_status` 字段会体现出跳过和代理命中的细节：

```Plain Text
[
  {
    "source_type": "adela",
    "enabled": true,
    "success": true,
    "message": "answered_by_agentic_aggregate"
  },
  {
    "source_type": "document",
    "enabled": true,
    "success": true,
    "message": "skipped_by_agentic_aggregate"
  }
]
```

## 测试体验

使用项目之前的unified 问答接口：

```Plain Text
curl -N -X POST http://127.0.0.1:6060/api/v1/rag/chat_engine/unified_query \
  -H 'Content-Type: application/json' \
  -d '{
    "query": "现在总共部署了多少个模型？",
    "stream": true
  }'
```

系统应当能准确判断意图，快速返回类似“根据 adela 数据源统计，目前总共部署了 xxx 个模型...”的精确答复。

## 案例

下面案例基于当前 `data/index/gbrain.sqlite3` 实际运行得到，重点展示输入如何被转换成结构化统计计划。可以看到，不同问法最终都会落到“选择数据源 -> 绑定字段条件 -> 执行过滤 -> 去重或计数”的通用流程。

### 案例 1：统计已部署模型数

**输入内容**

```Plain Text
现在总共部署了多少个模型？
```

**执行过程**

```JSON
{
  "source_type": "adela",
  "operation": "count_unique",
  "count_field": "model_name",
  "dedupe_field": "model_name",
  "count_semantics": "model_variant",
  "condition_logic": "all",
  "field_conditions": []
}
```

系统会读取 Adela 部署记录，未额外限定平台、状态或业务方向时使用全量 Adela metadata 行；随后按 `model_name` 去重计数。当前索引中参与统计的 Adela 记录为 487 条，去重后模型数为 154 个。这里统计的是“部署过的模型数量”，不是部署记录条数。

**最终输出示例**

```Plain Text
按 Adela 部署记录统计，匹配到 487 条部署记录，按 model_name 去重为 154 个模型。
```

### 案例 2：按平台统计部署记录

**输入内容**

```Plain Text
T4 平台上一共有多少条部署记录？
```

**执行过程**

```JSON
{
  "source_type": "adela",
  "operation": "count_records",
  "count_field": "row_id",
  "dedupe_field": "",
  "count_semantics": "deployment_record",
  "condition_logic": "all",
  "field_conditions": [
    {
      "field": "platform",
      "operator": "contains",
      "values": ["T4"]
    }
  ]
}
```

系统会先把“T4 平台”绑定到 Adela 的 `platform` 字段，而不是在整条文本里做无约束关键词扫描；过滤出 `platform` 包含 `T4` 的部署行后，按记录数直接计数。当前索引中 Adela 原始记录为 487 条，过滤后记录为 190 条；如果改问“T4 平台上部署了多少个模型”，同一过滤条件下按 `model_name` 去重为 124 个模型。

**最终输出示例**

```Plain Text
当前 Adela 部署记录中共有 190 条记录。统计口径：deployment_record；参与统计记录数 190 / 原始记录数 487。
```

### 案例 3：按业务目标统计模型发版数量

**输入内容**

```Plain Text
统计目标为人脸的算法都有哪些？
```

**执行过程**

```JSON
{
  "source_type": "table",
  "operation": "count_unique",
  "count_field": "model_name",
  "dedupe_field": "model_name",
  "count_semantics": "model_variant",
  "condition_logic": "all",
  "field_conditions": [
    {
      "field": "target_name",
      "operator": "contains",
      "values": ["人脸"]
    }
  ]
}
```

系统会把“目标为人脸”绑定到模型发版汇总表的 `target_name` 字段，并在匹配行中按 `model_name` 去重；如果问题同时要求“有哪些”，回答会补充算法名称列表或样例值。当前索引中 table 原始记录为 293 条，过滤后记录为 83 条，涉及 23 个算法、83 个模型。

**最终输出示例**

```Plain Text
匹配到 83 条模型记录、23 个算法、83 个模型。算法包括：deepcode-方舟标品、facebody、pageant、人脸关键点、人脸姿态、人脸属性、人脸手掌检测、人脸检测0系列、人脸检测3系列1、人脸检测3系列2、人脸检测4系列、人脸检测4系列-适配、人脸检测8系列、人脸特征、人脸特征-PK、人脸特征PK-2024&2025聚类、人脸特征PK-2024&2025识别、人脸特征PK-2024识别、人脸特征PK-2025聚类、安防方向-人脸二分类、安防方向-人脸大角度二分类、安防方向-人脸模糊、安防方向-人脸质量。
```
