# 统计功能 (Agentic Aggregate) 说明文档

## 功能简介

本项目在检索增强生成 (RAG) 的基础上，新增了**智能聚合统计（Agentic Aggregate）功能**。当用户提出需要进行全局数据统计、数量计算或状态汇总类的查询（例如：“现在总共部署了多少个模型？”）时，系统能够通过智能路由识别用户意图，并将此类请求直接交由分析代理（Agent）进行处理，而不是使用常规的文本块检索和阅读理解。

## 工作原理

1. **意图识别与路由 (`route_plan`)**
   当系统接收到查询词 `query` 时，利用 LLM 进行意图识别。如果判断该查询是一个明显的“统计/聚合查询”意图，路由模块会指定其走向 Agentic Aggregate 流程。

2. **数据源代理执行 (以 Adela 数据源为例)**
   系统直接拉取对应结构化或半结构化数据源的全局或条件筛选数据。例如直接接入数据库或 API 读取元数据记录。
   随后对匹配的条目（例如按照唯一的 `model_name`）进行计数与分组汇总，计算出结果。

3. **短路响应 (Short-circuit Response)**
   当某一个数据源成功完成统计分析并产出最终结果后，系统会：
   - 产生类似于 `answered_by_agentic_aggregate` 的状态消息。
   - 跳过其他不相关的数据源检索（标记为 `skipped_by_agentic_aggregate`），直接返回确切答案，从而大幅降低无效的检索消耗和推理延迟。

## 接口响应示例

在客户端中，调用统一查询接口时，若触发了此统计功能，其 `source_status` 字段会体现出跳过和代理命中的细节：

```json
[
  {
    "source_type": "adela",
    "enabled": true,
    "success": true,
    "message": "answered_by_agentic_aggregate"
  },
  {
    "source_type": "document",
    "enabled": true,
    "success": true,
    "message": "skipped_by_agentic_aggregate"
  }
]
```

## 测试体验

你可以使用项目自带的样例脚本进行测试：

```bash
python sample_code/unified_chat_api_client.py
```

或者显式指定你要统计的问题环境变量：

```bash
RAG_SAMPLE_QUERY="现在总共部署了多少个模型？" python sample_code/unified_chat_api_client.py
```

系统应当能准确判断意图，快速返回类似“根据 adela 数据源统计，目前总共部署了 xxx 个模型...”的精确答复。
